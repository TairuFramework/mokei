# Flow runtime (`@mokei/flow-host`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@mokei/flow-host`, a portable runtime that runs decision flows with run identity, approval, an inbox, tracing and recovery, and rewire the flow rig onto it.

**Architecture:** Prerequisite fixes land first in existing packages (task manager disposal and trace context, `DecisionFlowWiring.authorize`, the content validator move, a desktop input surface). Then `@mokei/flow-host` is built bottom-up: store and transitions, start and execution, inbox, recovery and dispose, tracing. The rig shim and its integration suite close the plan.

**Tech Stack:** TypeScript, vitest, `@sozai/event`, `@sozai/otel` (`@opentelemetry/sdk-trace-base` in tests only), pnpm workspace, Node test runner for `scripts/flow-rig`.

**Spec:** `docs/superpowers/specs/2026-10-01-flow-host-design.md`

## Global Constraints

- Conventions: `type` not `interface`, `Array<T>`, no `any`, `#private` fields, `ID` casing (`runID`, `taskID`, `traceID`), kebab-case file names, `import type` for types.
- Wire fields keep their protocol spelling (`taskId` from MCP results, `inputRequests`, `lastUpdatedAt`).
- `@mokei/flow-host` is portable: no `node:` imports in `src/`. IDs from `crypto.randomUUID()`.
- New package version `0.14.0`, same `package.json` shape as `packages/decision-flow-server/package.json`, added to `versioning.fixed` in `pnpm-workspace.yaml`.
- `_meta` key for the run ID: `dev.mokei/flow-run`.
- Changesets: patch only.
- No plan or task labels in code, comments or test names.
- Comments terse, British spelling in prose and comments.
- Codex implementers cannot run `pnpm` or `git`. Use `../../node_modules/.bin/vitest run`, `../../node_modules/.bin/tsc --noEmit --skipLibCheck -p tsconfig.test.json` from the package directory, `node_modules/.bin/biome check --write <files>` from the repo root, and `node --test 'scripts/flow-rig/test/*.test.mjs'`. Cross-package tests resolve built `lib/`: when a task changes a dependency package, the controller rebuilds it (`pnpm --filter <pkg> build`) before dependants are tested. The controller commits.

## Review Focus

- A registered flow whose input schema has required fields: `start({ flow, input })` must pass `input` as the tool arguments, not `{ input }` (Task 6 test "registered flow with required input").
- An approval answered twice at once, or answered while `cancel` runs: exactly one task, never a task for a cancelled run (Task 6 tests).
- A poll that resolves after an answer was sent: the item must not come back or settle as `withdrawn` (Task 7 test).
- A host disposed while the flow waits on a sibling task: the sibling must survive and the recreated host must finish the run (Tasks 1 and 8 tests).
- Runs with no OTel SDK registered: no `traceID`, no crash, same behaviour (Task 9 test).
