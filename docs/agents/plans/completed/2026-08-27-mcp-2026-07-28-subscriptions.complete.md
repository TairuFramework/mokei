# MCP `2026-07-28` Subscriptions (`subscriptions/listen`) — complete

**Status:** complete
**Date:** 2026-08-27
**Branch:** `feat/mcp-2026-07-28-subscriptions`
**Milestone:** piece E / B4 (SEP-2575) of the `2026-06-08-mcp-2026-07-28-migration` milestone — the last capability gap in the spec migration.

## Goal

Implement MCP `2026-07-28` `subscriptions/listen` (SEP-2575) end to end — client receive, server serve, `@sozai/event` producers, host events — over stdio and Streamable HTTP. A listen is one long-lived client→server request whose response stream stays open, carrying every opted-in out-of-band notification (`toolsListChanged`, `promptsListChanged`, `resourcesListChanged`, per-URI `resourceSubscriptions`). It replaces the GET/SSE endpoint plus `resources/subscribe` that `2025-11-25` used. `2026-07-28` only; the `2025-11-25` `resources/subscribe`/`unsubscribe` dispatch gap is deliberately left unimplemented (add only if a real peer needs it).

## Architecture & key design decisions

- **Unified execution model.** Every listen is served by a normal `ContextServer` via a new held-response primitive in `ContextRPC`; there is no special listen server. The *durable* server owns a shared `SubscriptionHub` (cross-connection registry + producer fan-out) that per-POST transport-isolated servers **borrow** on stateless HTTP.
- **Correlation.** `subscriptionId == the listen request's JSON-RPC id`. The client models a listen as a stream exchange fed by an optional notification correlator (`routeStreamNotification`). `META_SUBSCRIPTION_ID = 'io.modelcontextprotocol/subscriptionId'` — in `params._meta` on streamed notifications, in `result._meta` on the terminal.
- **Authoritative wire shape** is `@modelcontextprotocol/core@2.0.0`. The terminal `subscriptions/listen` result carries **only** `result._meta[subscriptionId]` — no `resultType` field (an earlier `resultType: 'complete'` requirement was a design error, verified and dropped).
- **Held-response state machine** (`ContextRPC`): `running → detached → terminal-writing → removed`. The scheduler reclaims the concurrency slot on detach but keeps duplicate-id + cancellation ownership until `completeDetached(id)`. `ContextRPC` owns only the terminal promise/write and builds the JSON-RPC envelope; `wrapResult` stays in `ContextServer` (the held terminal is already-wrapped). cancel-vs-terminal is first-settlement-wins with one cleanup path.
- **Hub keying** is `connectionID` (internal, minted via `@sozai/runtime` `getRandomID()`, never on the wire) then `subscriptionID`, so two stateless clients reusing request id `0` do not collide. Fan-out routes through each serving server's own notify path; it never locates an HTTP response by subscriptionId.
- **Backpressure** is per-subscription, serialized, bounded (`SubscriptionWriter`, 256-frame cap, disconnect-on-overflow). Ack is **written** before the registry entry is published (ack-first), so a producer event can never target a stream the client has not seen acknowledged.
- **Client `SubscriptionDriver`** is generation-based: open-and-ack the new filter before retiring the old (no gap/dupe), frame-gate superseded generations, and serialize mutations *and* reconnect on one queue. Reconnect backs off 1s→30s.
- **Disposal** runs a `_beforeTransportClose` hook (owner-only `hub.endAllGracefully()`) plus a held-response flush under a single 5s deadline; a graceful `complete()` awaits its terminal write so completion is never reported before the result reaches the wire.
- **Host integration is mechanism, not policy:** the host keeps its aggregate correct and emits host events (`tools:changed`, `prompts:changed`, `resources:changed`, `resource:updated`) for `2026-07-28` contexts; consumers drive reactions.

## What was built

New `subscriptions.ts` modules in `context-protocol` (schemas), `context-server` (`SubscriptionHub`, `SubscriptionWriter`), `http-server` (`runSubscriptionExchange`), and `context-client` (`SubscriptionDriver`); held-response primitive + stream-notification correlator + `ExchangeRegistry.close` + async disposal in `context-rpc`; `streamEvents.closed` in `http-client`; host events in `@mokei/host`. `HTTPHandler`/`ServeHTTPResult`/`SessionManager` disposal became async; `createServer` factory is `({transport, subscriptionHub, connectionID}) => ContextServer`.

## Validation

Executed subagent-driven (19 tasks, per-task review + final whole-branch review), then **two independent Codex review passes** post-QA. All actionable findings fixed: held-write ordering + registration race, disposal deadline covering the pre-close hook, stateless-borrower teardown on writer failure (backpressure/write-rejection now disposes the per-POST server and closes its SSE body), terminal-closes-the-exchange, concurrency cap (`maxSubscriptionExchanges`), client orphan-listen + throwing-`onRetry` guards, host disposal via `client.dispose()`, and `resourceSubscriptions` loosened to plain strings for core interop. Real-SDK interop validated both directions (mokei client ↔ SDK v2 server and SDK v2 client ↔ mokei server), including two clients reusing request id `0` against one durable hub. Full-workspace `build:types` green; all touched-package tests + interop suites pass.

## Follow-on work

Two hardening items are logged in `docs/agents/plans/backlog/2026-06-20-mcp-2026-07-28-deprecations-cleanup.md` (§4), to land alongside the deprecations/cleanup piece:

- **`#disposing` inbound-request gate** — a disposing server keeps its read loop live during the ≤5s flush window, so it can admit new requests until `#close` (benign: `abortAll` sweeps them; a `#disposing` flag would stop new work starting).
- **SSE stream reader backpressure** — `createSSEStream` enqueues without consulting reader demand, so `SubscriptionWriter`'s bound only trips on a fast producer, not a slow network reader. Shared infra (session/stateless/subscription streams); the fix needs cross-consumer validation.
