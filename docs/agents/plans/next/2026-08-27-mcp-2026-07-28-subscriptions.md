## Scope

**B4 `subscriptions/listen` replaces the GET endpoint + `resources/subscribe` (SEP-2575).**
Rewrite the HTTP server/client streaming. Depends on U1 (built); parallel with the shipped B7.

Two branches, either implementable on its own:

### `2026-07-28` branch — `subscriptions/listen`

The finalized `2026-07-28` streaming surface. Still **unexercised against mokei** (was §3.2.4).
Not yet wired.

The U1 streaming arm and continuation store are built, unit-tested and hardened, but have **no
wire trigger yet** (`context-rpc` `exchange.ts` / `continuation.ts`). B7 (MRTR) shipped as a
request-level retry loop and did not wire into that seam — it has no streaming or continuation
state to correlate. **B4 is the only remaining candidate consumer of `_registerStreamExchange`.**
Whether B4 wires into it is B4's own call when picked up; nothing is open on the registry itself.
The remaining registry decision (server-minted handles) lives in the milestone's open questions.

### `2025-11-25` branch — `resources/subscribe`

Folded from the retired `2026-07-02-mcp-feature-gaps.md` (gap 3) and §3.3.3 of the source plan.

The `2025-11-25` protocol types exist (`subscribeRequest` / `unsubscribeRequest` /
`resourceUpdatedNotification` in `context-protocol/src/resource.ts`) but there are **no client
methods, no server dispatch, and no `resources.subscribe` capability declaration**. Since mokei
keeps `2025-11-25` per the coexistence decision, a `2025-11-25` peer may still expect this
surface. Implement it as the `2025-11-25` branch of B4 **only if a real peer needs it.**

**Do not simply widen `clientMethods`.** `packages/context-protocol/src/versions/2025-11-25.ts`
lists eleven client methods, omitting both subscribe/unsubscribe, although `clientRequest` /
`clientMessage` do include `subscribeRequest` / `unsubscribeRequest`.
`packages/context-server/src/server.ts` gates *inbound* requests on that same set
(`if (!protocol.clientMethods.has(request.method))` → `METHOD_NOT_FOUND`), so widening the table
changes server behavior: mokei would start accepting subscribe/unsubscribe requests it has no
dispatch for. Add the methods together with the dispatch and capability, not on their own.
