# MRTR — multi round-trip requests on `2026-07-28` (piece D)

**Status:** next
**Origin:** `backlog/2026-06-20-mcp-draft-remaining.md`, §2 item 6 (B7).
**Milestone:** `milestones/2026-06-08-mcp-draft-migration.md`

The deepest remaining piece of the `2026-07-28` work, and the reason the revision is not yet at
capability parity with `2025-11-25`.

## What is missing

SEP-2322 replaces server-initiated requests with `inputRequests` / `inputResponses` sub-exchanges.
Mokei implements neither side: on `2026-07-28` the client and the server both refuse
`sampling/createMessage`, `elicitation/create` and `roots/list` at setup with
`MRTRNotSupportedError`. Those three capabilities exist on `2025-11-25` only.

The wire schema already admits a spec-shaped suspended result (`inputRequiredResult` in
`context-protocol/src/versions/2026-07-28.ts`), so the client's refusal fires with its own error
rather than a generic validation failure. Nothing consumes `inputRequests` or sends
`inputResponses`.

## Scope

1. Consume `inputRequests` and send `inputResponses` on the client; emit them on the server.
2. Dismantle the bidirectional `request()` / `#sentRequests` path in `context-rpc` for this
   revision. The seam is `_registerStreamExchange` (`exchange.ts` / `continuation.ts`) -- the U1
   streaming arm and continuation store are built, unit-tested and hardened, with no wire trigger
   yet.
3. Tighten `withResultType` to `const: 'complete'`. It currently admits `'input_required'` on
   every terminal branch, so a `callToolResult`-shaped frame labelled `input_required` validates.
4. Restore `sampling`, `elicitation` and `roots` on `2026-07-28`, removing the setup-time
   refusals.
5. `-32021` `MISSING_REQUIRED_CLIENT_CAPABILITY` becomes reachable: today `PROTOCOL.serverMethods`
   is empty, so no handler can need an undeclared client capability and the constant has no
   emitter (§3.3.1). The ladders in §3.2.4 become testable at the same time.
6. The roots list-changed half of B6, which belongs here -- roots only exist through MRTR on
   `2026-07-28`.
